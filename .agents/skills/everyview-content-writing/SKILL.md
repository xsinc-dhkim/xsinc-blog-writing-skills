# 에브리뷰 콘텐츠 작성

사용자가 검토하고 수정할 수 있는 에브리뷰 공식 블로그 초안과 검수 제안을 만든다. 실제 게시와 브랜드 공통 규칙 변경은 수행하지 않는다.

## 작업 순서

1. [공식 채널과 현재 범위](references/everyview-baseline.md)를 읽고 요청이 현재 운영 범위인 `에브리팁`에 해당하는지 확인한다.
2. 요청에서 이미 제공된 정보를 먼저 추출한다.
3. 새 글 작업을 시작할 때 공식 블로그 맥락 스캔을 수행한다. 최근 주제 흐름, 톤앤매너, 유사·중복 주제, 참고할 글, 새 자료와 충돌할 수 있는 내용을 짧게 정리한다. 접근하지 못했으면 스캔했다고 말하지 않고 최근 게시물 링크·본문·화면을 요청한다.
4. `에브리뷰 블로그 글 만들자`처럼 요청이 짧으면 맥락 스캔 결과를 먼저 보여주고 브리프 인터뷰를 시작한다.
5. 브리프 인터뷰는 현재 답할 수 있는 미결정 사항을 한 라운드에 모아 번호를 붙여 묻고, 각 질문에 추천안을 덧붙인다. 먼저 주제, 독자·목적, 사실 근거를 확인하고, 답변에 따라 새로 열린 질문만 다음 라운드에서 묻는다. 사용자가 이미 답한 내용과 블로그에서 확인한 게시 이력·문체·주제 맥락은 다시 묻지 않는다.
6. 질문은 사실성이나 초안 방향을 바꾸는 항목까지만 이어간다. 선택적 키워드·이미지·CTA는 추천안으로 채울 수 있으며, 핵심 정보가 모이면 인터뷰를 끝낸다.
7. 기존 게시물은 문체·구조·주제 맥락 참고자료로만 사용한다. 과거 게시물의 서비스 기능, 가격, 지원 범위와 운영 상태를 현재 사실로 간주하지 않는다.
8. 확인된 사실, 해석, 확인 필요 항목을 구분해 [브리프](references/brief.md)를 완성하고 사용자 승인을 받는다. 상세 지시가 충분해 인터뷰 질문을 생략해도 브리프 승인은 받는다. 승인 전에는 전체 본문을 작성하지 않는다.
9. 승인된 브리프를 기준으로 제목 후보와 전체 초안을 작성한다. 사실 근거가 없는 기능, 수치, 효익과 이용 조건은 만들지 않고 `확인 필요`로 표시한다.
10. [에브리팁 작성 기준](references/everytip-guide.md)과 [검수 기준](references/review-checklist.md)으로 전체 원고를 확인하고 `통과 / 수정 제안 / 확인 필요`를 짧게 덧붙인다.
11. 피드백을 받으면 먼저 브리프의 변경점을 보여주고, 승인 후 전체 원고와 검수를 다시 생성한다.

질문 형식은 다음처럼 간결하게 유지한다.

```markdown
❓ Q1 — 질문 제목: 결정할 내용을 묻는다.
➡️ 추천: 현재 근거에서 가장 적합한 선택과 짧은 이유
```

## 피드백과 개선

- 한 글의 피드백은 해당 브리프에만 적용한다.
- 반복되거나 명시적으로 공통화한 피드백은 `Skill 개선 후보`로 제안한다.
- 사용자가 승인한 후보만 이후 Skill 개정 입력으로 취급한다. 대화만으로 설치된 Skill 파일이 자동 변경됐다고 말하지 않는다.

## 권한과 범위

- 현재 기본 지원 범위는 `에브리팁`이다.
- OTT와 AI 카테고리는 향후 운영 계획으로만 알려져 있다. 실제 운영과 작성 기준이 확인되기 전에는 지원 중이라고 표현하거나 전용 원고를 작성하지 않는다.
- 고객지원 정책, 환불, 정산, 계정, 이용권과 서비스별 제공 조건은 현행 근거가 있을 때만 설명한다.
- 이 Skill은 게시, 예약 발행, CMS 편집과 최종 승인을 수행하지 않는다.
