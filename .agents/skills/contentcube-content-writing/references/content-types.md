# 글 유형별 구조 안내

아래 구조는 브리프를 만드는 출발점이다. 글의 근거와 목적에 맞게 조정하고, 조정한 구조를 사용자에게 승인받는다.

## 기능 소개

- 제목은 `콘텐츠큐브 호텔리어 | 제목` 형식을 사용한다.
- 원고는 의미상 네 덩어리로만 구성한다.
  1. 서론: 소제목 없이 기능이 필요한 상황과 글에서 알 수 있는 내용을 소개한다.
  2. 본론 1: 소제목을 두고 기능의 작동 방식과 실제 이용 순서를 설명한다.
  3. 본론 2: 소제목을 두고 활용 방법, 운영자가 얻는 확인된 효익과 적용 조건을 설명한다.
  4. 결론: 소제목을 두고 핵심 가치를 요약하고 문의 CTA로 마친다.
- 추가 정보는 위 네 덩어리 안에 배치하며 다섯 번째 병렬 단락을 만들지 않는다.

## 기능 업데이트

- 제목은 `콘텐츠큐브 업데이트 | 제목` 형식을 사용한다.
- 원고는 의미상 네 덩어리로만 구성한다.
  1. 서론: 소제목 없이 업데이트 내용과 독자가 확인할 이유를 소개한다.
  2. 본론 1: 소제목을 두고 구체적인 변경 전후와 실제 이용 상황을 설명한다.
  3. 본론 2: 소제목을 두고 이용·설정 방법, 운영자가 확인할 지점, 적용 조건과 제한을 설명한다.
  4. 결론: 소제목을 두고 업데이트의 의미를 요약하고 문의 CTA로 마친다.
- 기존 기능과 새 변경을 구분하고, 추가 정보는 위 네 덩어리 안에 배치한다.

## 이용 방법

`목표 → 준비·적용 조건 → 순서별 실행 → 완료 확인 → 자주 막히는 지점·제한 → 문의 CTA`로 구성한다.

## FAQ

질문을 독자의 과업별로 묶고, 각 답변을 `짧은 결론 → 필요한 조건·예외 → 확인 경로` 순으로 쓴다. 확인되지 않은 답변은 `확인 필요`로 분리한다.

## 서비스 소식

`무슨 소식인지 → 대상과 시점 → 이용자에게 달라지는 점 → 필요한 다음 행동 → 문의 CTA`로 구성한다. 계획과 이미 적용된 운영 상태를 구분한다.

이용 방법·FAQ·서비스 소식의 고정 제목 형식은 아직 확인되지 않았다. 사용자가 정하지 않았으면 제목 후보를 제안하되 공통 규칙으로 확정하지 않는다.
