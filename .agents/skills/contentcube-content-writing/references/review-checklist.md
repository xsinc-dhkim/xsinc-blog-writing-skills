# 원고 검수 기준

## 사실과 근거

- 기능·수치·적용 범위·시점이 글별 원천에 연결되는가.
- 화면에 보이는 항목과 실제 사용 가능 상태를 구분했는가.
- 미확인 효익과 보장 표현을 제거하거나 `확인 필요`로 표시했는가.
- 첨부 이미지의 내용과 설명이 일치하는가.

## 독자와 전개

- 처음 접하는 독자가 서비스·용어·글을 읽을 이유를 이해할 수 있는가.
- 독자의 상황을 임의로 단정하지 않았는가.
- 승인된 브리프의 목적·핵심 메시지·구조를 따르는가.
- 블로그 맥락 스캔에서 확인한 최근 주제와 불필요하게 중복되거나 충돌하지 않는가.
- 기능 나열에 그치지 않고 확인된 운영상 의미가 드러나는가.

## 문체와 형식

- 친근하고 전문적인 해요체가 일관되는가.
- 기능 소개 제목이 `콘텐츠큐브 호텔리어 | 제목`, 기능 업데이트 제목이 `콘텐츠큐브 업데이트 | 제목` 형식을 따르는가.
- 단락 수와 소제목 구성이 글의 목적·자료량에 맞고 승인된 브리프의 구조를 따르는가.
- 설명을 나열하기보다 실제 이용 상황과 운영자가 확인할 지점이 읽기 쉽게 이어지는가.
- 공식 블로그 참고 게시물이 최신 흐름과 주제에 관련 있고, 사용자가 브리프에서 정한 기간·제외 조건을 따르는가.
- 키워드가 지정됐다면 억지스럽게 반복하지 않았는가.
- 임시 표기와 자리표시자가 남아 있지 않은가.
- CTA가 브리프의 목적·권한 범위와 맞는가.

## 보고 형식

원고 뒤에 아래 형식으로 짧게 보고한다.

```markdown
## 검수 결과

- 판정: 통과 / 수정 필요 / 판단 보류
- 통과:
- 수정 제안:
- 확인 필요:
- Skill 개선 후보: 없음 또는 제안 1건
```

핵심 기능, 적용 범위, 결제수단이나 운영 조건에 `확인 필요`가 남아 있으면 판정은 `판단 보류`다. 제목·구조·참고 범위처럼 다음 글에도 재사용되는 정정이 나오면 Skill 개선 후보를 `없음`으로 쓰지 않는다.
