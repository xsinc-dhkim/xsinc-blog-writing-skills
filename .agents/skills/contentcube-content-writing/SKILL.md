# 콘텐츠큐브 콘텐츠 작성

사용자가 검토하고 수정할 수 있는 블로그 초안과 검수 제안을 만든다. 실제 게시와 브랜드 공통 규칙 변경은 수행하지 않는다.

## 작업 순서

1. 요청에서 글 유형을 `기능 소개 / 기능 업데이트 / 이용 방법 / FAQ / 서비스 소식` 중 하나로 정한다. 불명확할 때만 질문한다.
2. [초기 작성 기준](references/contentcube-baseline.md)과 선택한 유형의 [구조 안내](references/content-types.md)를 읽는다.
3. 사용자가 지정한 자료만 읽고 확인된 사실, 해석, 확인 필요 항목을 구분한다. 공개 블로그는 문체·구조 참고용이며 과거 글의 상품 사실을 현행으로 간주하지 않는다.
4. [브리프 양식](references/brief.md)의 모든 항목을 채워 사용자에게 보여준다. 상세 지시가 충분해도 브리프 승인은 생략하지 않는다. 승인 전에는 본문을 작성하지 않는다.
5. 승인된 브리프를 기준으로 제목 후보와 전체 초안을 작성한다. 확인되지 않은 기능·수치·효익은 만들어내지 않고 `확인 필요`로 표시한다.
6. [검수 기준](references/review-checklist.md)으로 전체 원고를 다시 확인하고 `통과 / 수정 제안 / 확인 필요`를 짧게 덧붙인다. 검수 결과는 추천이며 원고를 자동 승인하지 않는다.
7. 피드백을 받으면 먼저 브리프를 갱신해 변경점을 보여주고, 승인 후 전체 원고와 검수를 다시 생성한다. 특정 문단만 덧대어 이전 기준을 잃지 않는다.

## 피드백과 개선

- 한 글의 피드백은 해당 브리프에만 적용한다.
- 반복되거나 명시적으로 공통화한 피드백은 `Skill 개선 후보`로 제안한다. 후보에는 바꿀 규칙, 적용 글 유형, 기존 결과에 미치는 영향을 적는다.
- 사용자가 승인한 후보만 이후 Skill 개정 입력으로 취급한다. 현재 실행 중인 Skill 파일을 대화만으로 자동 변경했다고 말하지 않는다.

## 권한 경계

- 사용자는 초안과 Skill 개선 후보를 검토·수정한다.
- 외부 게시의 최종 승인은 조직이 지정한 승인자가 담당하며, 이 Skill은 게시·예약·CMS 편집을 수행하지 않는다.
- Notion·시트·사내 자료는 사용자가 지정한 페이지나 범위만 읽는다. 연결 여부만으로 전체 자료 접근을 가정하지 않는다.
- 키워드는 사용자가 지정하거나 확인된 원천이 있을 때만 적용한다. 없으면 메인 키워드 1개와 서브 키워드 0~2개를 요청하고, 사용자가 키워드 없이 진행하겠다고 하면 생략한다.
